# Qwen3-32B code-edit：17轮指引复现

在 CodeEditorBench code-debug 工作负载上优化 Qwen/Qwen3-32B 的多请求服务能力。
唯一性能目标是 benchmark JSON 的 **`max_throughput_tok_per_sec`**：
在单个 **5 req/s open-loop Poisson 到达负载**下，最大化
`所有逻辑请求成功输出的总 token / 从首个计划到达到最后请求完成的墙钟秒`。
不 sweep request rate。客户端不设并发上限、不等待响应再派发；
实际并发、排队和 batch 由引擎决定。不是固定并发优化，也不是单请求中位 tok/s。
固定样本、到达随机种子和生成预算，保留实际峰值在途数、派发延误和重试记录。
引擎拒绝、drop、连接中断、截断流或空输出后重试同一原始请求，
退避、失败尝试和尾部排空均计入墙钟；仅最终成功输出计一次 token。
总完成期限内仍有失败或客户端发压滞后则整次评测失败，不得丢弃困难请求抬高成绩。

先建立正确可测的 eager BF16 AR 服务基线。支持多请求、正确的请求级 KV 隔离
和服务生命周期是工作负载基础要求，不可通过串行客户端伪造并发吞吐。
先提名基线供框架正式 accuracy/benchmark，再提交优化候选；
in-turn 自测不能代替 baseline/official receipts。如无收益，应保留可信 incumbent。

## 固定轮次合同

这是按给定 execution plan 顺序重做的独立实验，不是自主排序优化。
必须按下列第01至17轮依次执行，框架提示中的 `round_number` 是唯一轮次来源。
启动前框架自动测量的 baseline 不占第01轮；第01轮仍需完成控制提名及正式评测。
inner重试、judge、局部验证和故障恢复不推进计划序号，也不重置任何预算。
本轮结束时不得请求跨outerloop的`continue`。最迟最后一次inner回复须诚实报告
完成、失败或受阻状态，并将`next_step`留空；未完成的修复建议写进证据或总结，
不能借非空`next_step`申请下一outerloop继续旧假设、挤占下一份指引。
每轮只执行该轮的一项方案；不能提前实现后续项、跳过某项或额外插入一轮，
不能用“延续上一假设”代替本轮的新方案，也不能自主提前结束未完成的序列。
即使早期项未完成，仍按下一轮指引尝试；必要前提缺失时如实报告受阻，不夹带补做其他项。
同一类优化在多个指定轮出现是本次合同的要求，不适用“切走后永不重开”的自主阶段规则。

outerloop使用agent，inner使用multi-agent；严格17轮，每轮最多五次implementer机会。
显式设置
`--outer-loop agent --inner-loop multi-agent --max-rounds 17 --max-retries-per-round 5`。
所有设计、实现及评审都应写明框架轮次、本轮计划标题与唯一机制，
并按下列标识返回新的hypothesis id；允许追加描述后缀，不得改变规定前缀：

## 每轮execution plan

以下只规定可迁移的机制与正确性边界，不指定实现文件、函数或既有代码结构。
实现细节由agent按当前真实服务设计；每轮使用同一严格accuracy和完整5 RPS benchmark。

### 第01轮：服务控制测量

保持生产计算、请求调度和运行依赖不变，确认服务能够真实加载BF16权重，执行带KV缓存的逐token生成、流式输出和逐位置logprob观测。检查请求独立性、停止条件、取消及资源释放，保留实际执行证据。

通过严格精度门禁后，以固定平均5 RPS开放到达压测；从第一计划到达到最后请求完成统计成功输出吞吐，排队、重试、退避和排空均计时。仅建立可复现的控制读数，不把测量波动当作优化收益。

### 第02轮：Decode侧Continuous Batching

在生成步之间接纳新请求，完成或取消的请求独立退出。每步收集已完成prefill且可继续生成的请求，各取一个输入token，打包执行共享dense投影、归一化、MLP和输出投影，批量argmax并统一回传；attention及历史KV处理仍逐请求执行。

各请求保留独立KV、位置、掩码及输出预算，不填充无效请求，不等待凑批。Prefill仍逐请求整段执行，与decode batch轮流调度。按容量准入，正确处理背压及在途释放。验证异长请求共同推进、新请求中途加入和逐请求数值一致性，再测完整服务吞吐。

### 第03轮：FlashInfer分页Attention

以FlashInfer分页attention替换显式attention计算。为每个请求独占分配KV页，将新增K/V直接写入对应页，避免逐步拼接完整历史KV及展开重复KV头；共享decode使用分页decode，prefill和多token续写使用因果分页prefill。

每次forward构造一次请求长度、页表和位置元数据，并跨层复用。保持BF16、请求隔离、位置编码和采样语义；完整预留请求KV预算及工作区，取消或完成后等待在途计算结束再释放。验证异长、多token、取消和页复用，再检查严格精度及开放负载吞吐。

### 第04轮：按实际存活张量核算Attention工作区

针对分页attention服务审计一次forward的真实分配与张量存活期，移除已不存在的历史KV拼接、重复KV头展开及稠密attention矩阵预留，以仍实际分配的张量重建保守峰值上界。

区分输入query行与真正投影的输出行，计入分页元数据、库工作区和分配器粒度，避免只按理论元素字节低估占用。保持KV物理池、完整请求预算、安全预留、FIFO准入及数学计算不变。通过分配来源核对、容量边界测试及严格精度验证，确认驻留能力提升不是任意放宽内存限制，再测完整服务吞吐。

### 第05轮：区分持久KV与共享临时空间

对不会重叠执行模型forward的服务，将请求持久KV占用与执行期间可复用的临时工作区分别计账：所有驻留请求的完整KV预算累加，临时空间按可能执行的最坏合法forward核算，避免为每个请求重复永久预留同一工作区。

覆盖聚合decode、单请求prefill、多token观测及元数据，不能把各请求的单独峰值简单取最大而漏算组批峰值。保持物理池、安全预留、FIFO及计算语义不变，证明所有合法调度仍满足峰值边界；验证释放、取消、容量等待和精度，再测高负载完整排空吞吐。

### 第06轮：融合RMSNorm

将RMSNorm的均方归约、加epsilon、倒平方根、归一化和权重缩放替换为FlashInfer融合原语，减少中间张量读写与逐算子启动开销。覆盖层内归一化、Q/K归一化及最终归一化，生成和logprob观测共用相同数学路径。

保持BF16输入、权重与输出，以及epsilon和归一化维度；适配张量视图时不引入隐式拷贝。不同时改变调度、容量策略或其他算子。用不同宽度及prefill、共享decode、多token续写验证数值和真实激活，启动观察结束后移除hook，再通过严格精度门禁及完整吞吐评测。

### 第07轮：融合RoPE

用FlashInfer融合RoPE替换旋转拆分、三角函数取值及逐元素组合操作，在单次融合调用中处理打包的Q/K。各token绝对位置来自所属请求的真实KV长度与本次输入偏移，不能使用统一batch位置。

保持BF16、旋转维度、非交错布局、频率参数和缩放规则；prefill、异长共享decode及多token续写共用同一路径，不改变attention、调度或内存收费。验证非零位置、不同请求长度及跨步续写，记录融合路径实际启用并通过严格精度门禁；吞吐比较同时披露实际KV容量，避免把容量变化误归为纯算子收益。

### 第08轮：精确活跃批大小CUDA Graph

为支持范围内的每种真实decode批大小建立独立稳定缓冲区，捕获从embedding到完整模型输出投影的GPU计算。重放前更新token、各请求位置与页表，不通过填充虚假请求凑固定batch，也不按上下文长度反复捕获。

元数据规划、逻辑KV提交、采样及请求生命周期留在图外；prefill、多token输入或不支持的形状走明确的非图路径。图存储单独设上限并计入容量，销毁前排空在途工作。用独立KV对比重放与非图计算，覆盖页复用和动态输入，确认正式负载实际重放，再测完整吞吐。

### 第09轮：原Prompt N-gram投机解码

仅用当前请求不可变的原prompt建立三token后缀索引，匹配后从原输入的最早匹配位置提议后续最多4个token；无匹配时正常decode。禁止prediction、预期答案、跨请求候选及从未来输出构造索引。

将最后已生成token与候选一次送入目标模型，按其greedy结果依次接受匹配前缀；在首个失配处提交目标token，全部匹配时可再提交一个目标token。KV只保留真实提交范围，丢弃未接受尾部，并限制生成、事件及容量预算。验证拒绝、回滚、续写和停止条件，再检查精度及完整排空吞吐。

### 第10轮：整段Prefill与Decode混合组批

轮到一个待prefill请求时，将其完整prompt与当前已就绪的decode或投机验证请求打包，共享一次模型forward和批量采样。Prefill只取末行输出，验证请求保留全部所需行，各请求使用独立位置、因果边界和KV。

按稳定队列顺序选择成员，以完整query、输出行、请求数及页表计算聚合临时空间；首个不适配的就绪请求处停止扩充。不等待新到达、不切分prefill、不缩短候选以凑批。验证混合结果、逐请求KV提交和取消隔离，确认真实混合执行，再以完整服务吞吐判断收益。

### 第11轮：双Prefill共同分派

一次调度先确定首个完整prefill及可共同执行的decode或验证请求，再尝试加入最早就绪的第二个完整prefill，最多两个。两段prompt可异长，以变长打包共享dense计算；没有decode时也允许两个prefill共同执行，各自只取最后一行生成首token。

按全部输入、输出与页表精确核算聚合空间。第二个请求不适配时保持已选成员及顺序，不改选更短prompt、不挤出decode、不缩短验证候选，也不等待凑批。验证双prompt隔离、行映射、独立完成和取消，记录真实共同分派并评测完整吞吐。

### 第12轮：已验证Prompt复制游标

在原prompt候选解码中，为每个请求维护可失效的位置游标。仅根据目标模型实际提交的token与原prompt连续匹配来建立、推进游标；当前三token后缀仍匹配该位置时，优先从对应原输入位置提议最多4个后续token，避免重复片段总跳回最早位置。

失配即清除游标并退回只读的最早匹配索引。候选来源始终限本请求不可变原prompt，未接受的候选不能推进游标；正常decode提交也遵守同一规则。保持目标模型逐token验证、KV回滚和输出预算，验证重复片段、失配及重建，再测精度与完整吞吐。

### 第13轮：对齐Prompt的长候选验证

在原prompt投机解码中，先按最多4-token候选确定并冻结本次成员、顺序及同行prefill，再对由真实提交token确认对齐的位置游标，将对应候选延长至最多16个token；未确认对齐仍最多4个。所有候选仅切取当前请求原prompt。

同时受原输入边界、剩余生成量、事件槽和KV预算限宽。以延长后的全部输入与验证输出重新核算聚合临时空间；不适配则整批恢复预备的短候选，不换成员或搜索替代批。目标模型逐token接受并回滚多余KV，验证失配、停止及同行prefill，按完整吞吐而非接受率单独判断收益。

### 第14轮：多Token验证CUDA Graph

对所有请求均已有KV、需要逐位置输出的多token验证，按精确请求数与总query行数缓存CUDA Graph；同形状第二次出现才捕获，缓存最多4项。不修改候选、成员选择或接受规则；prefill及混合prefill不走该图。

重放前更新请求边界、页表、位置和输入；显式检查执行签名，缓存满、形状不符或预算不足时走非图路径。图存储计入总上限。用独立KV验证不同分段、候选拒绝、回滚、页复用及续写一致性；评测捕获开销、命中和排空吞吐，不把图命中率当收益。

### 第15轮：合并MLP Gate/Up投影

对门控MLP，将gate与up的BF16权重按固定顺序沿输出维拼接为单块，用一次宽矩阵乘法替代对同一输入的两次投影，再以视图拆回两部分；保持SiLU、逐元素乘法及down投影不变，不混入其他算子融合。

加载时逐源核验拼接顺序和数值，限制临时权重占用，释放旧投影及暂存，保持最终物理权重字节与逻辑参数不变。覆盖多token、共享decode及图重放，验证分离与合并表达式的数值、KV和续写；按实际容量披露完整吞吐，不预设少一次投影调用必然更快。

### 第16轮：观测校准与平台期复测

保持默认生产执行不变，另以显式开启的有界host观测记录调度、图执行、验证和输出边界，避免新增逐请求设备读回或改变决策。对相同请求序列比较观测关闭与开启两种状态，检查输出、成员、候选宽度、接受、回滚及完成结果一致，量化观测开销。

分析时间线时区分GPU区间与剩余时间，避免嵌套区间重复计时；未测清的成本保持未知。正式吞吐使用观测关闭路径并通过严格精度门禁，不把诊断流量的阶段占比推广到正式负载，也不把复测波动计作优化。

### 第17轮：有Decode同行的Prefill切片

将prefill与就绪decode或目标验证共同分派，但先按完整剩余prompt及原候选宽度核算并冻结成员，再切分实际输入。有decode或验证请求同行时，每个prefill本次最多处理256个原prompt token；没有这类同行请求则处理完整剩余prompt。

中间切片只追加连续KV并记录位置，不采样、不生成输出、不推进复制游标；最后切片才生成首token，随后进入decode。不得借切片释放的空间额外加请求或加宽候选。验证多请求切片交替、KV连续性、独立取消和最终输出，权衡新增forward及首token等待成本，用严格精度与完整服务吞吐决定保留。

## 逐轮报告与保留

逐轮报告计划是否完成、inner次数、真实激活、accuracy及benchmark的正式receipt、
入口incumbent与本轮候选吞吐、最终保留决定及容量/输出变化；不能只展示正结果。
控制和诊断轮不记新增优化收益，无收益轮不替换更优incumbent。
第17轮结束后采用本次实验内真实测量且精度通过的最佳可信版本，禁止额外自由优化轮。
全部17轮都应报告实际状态，受阻或耗尽机会也占对应轮次，不能改号补跑。
同负载、设备、存储的新测量用于比较；不读取或复用历史实验成绩。
这些是累计服务上的逐轮改进，不是17项彼此独立的消融或统计显著性结论。

## 输入与精度

- 请求只发送原 prompt，不包含独立草稿或答案字段。n-gram 投机草稿只能从
  **当前请求原 prompt 的 token** 查找，不能读取 gold、参考文件或历史请求答案。
  草稿必须由同一生产 target forward 验证，禁止 echo、答案缓存及猜测 gate 输出。
- 前台 `run_server.sh --model-dir /model --port PORT`，真实模型就绪后 health 才返回 200；
  streaming `/v1/completions`，原样 tokenize preformatted prompt，关闭 thinking。
- 正确重建 Unicode SSE；输出 token 按完整文本重新 tokenize，不按 chunk 计数。
  每个请求均真实执行模型，保持请求状态隔离、EOS 和 max_tokens 语义。
- 实现 `accuracy_checker/README.md` 的 `/v1/logprobs` 和 SSE token ID 观测，
  复用生产 forward、权重、精度、attention、KV 及实际启用的优化，不另设 HF 旁路。
  HF BF16 参考固定：54 个 teacher-forced 位置，双向 top-5 至少 95%，
  HF top-1 token 的 logprob 最大绝对差 **<=0.2**。
